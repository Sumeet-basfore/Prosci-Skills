# L-001 — injected versus discovered skill delivery

Date: 2026-11-26
Authorization: 24 proxy-enforced requests per configuration, 48 total, $0.03 estimated ceiling.
Model: `claude-haiku-5-5` at thinking `low`, reached through the local proxy (`l001-proxy`).
Configuration hash `11d55557fc3bceeb`; skills fingerprint `56516c7902b258de`.

## What was held constant

Three scenarios, two repetitions, two arms, interleaved per scenario and repetition. The only planned
difference was whether the assigned skill body was part of the worker prompt.

| Scenario | Fixture base | Skill | Task |
|---|---|---|---|
| fix | `2d8031f3` | `prosci-fix` | make the failing suite pass, `src/` only |
| arch | `efa55b6d` | `prosci-architect` | write `docs/adr/0001-uploads.md` |
| review | `ca51a89f` | `prosci-review` | write `docs/review.md`, do not edit `src/` |

Discovery was available in both arms (`--skill` pointed at the same skill directory); the injected arm
additionally carried `prosci`, `prosci-bar` and the assigned skill body. Mean instruction size was 54 tokens
for the discovered arm and 5,594 tokens for the injected arm.

Isolation was checked before either arm started: sandbox verification passed and six credential/repository
probes were unreadable (`eval/reports/l001/isolation-discovered.txt`, `isolation-injected.txt`). Acceptance was
proved discriminating without a model: every fixture fails untouched and a hand-written correct artifact passes
(`vacuity.json`). Each run had its own single-use authorization record.

The 48-request cap ended the experiment before all twelve runs finished. Two runs were cut mid-answer by a

acceptance or adherence failures. The injected arm reached the cap sooner because it used more requests per run
(5.6 versus 4.55).

Three earlier preflight attempts failed before reaching the provider (auth entry missing `type`, agent directory
outside the sandbox bind, budget file not pre-created). They spent zero requests and are preserved under
`eval/runs/l001-invalid-*`; they are not part of the measurement.

## Findings

1. **Delivery was real.** The injected prompt contained the assigned body in all six attempted runs
   (`5620b3a…` fingerprint bound in the plan); the discovered prompt did not. Delivery alone is not scored as
   effectiveness.
2. **Procedure adherence was higher with injection in this sample**: 4/4 completed injected runs against 2/5
   discovered. The difference is concentrated in `arch` (injected 1/1, discovered 0/2) and `review` (1/1 versus
   0/1). `fix` tied at 2/2: both arms ran the failing test before editing.
3. **Strict acceptance was 4/4 injected versus 4/5 discovered.** The one failure, `discovered-review-r1`, was a
   substantively correct review that cited `src/validate.mjs` without a line number. The harness required
   `src/validate.mjs:<line>`, a convention the skill teaches but the visible brief did not state. This is a
   measurement defect that favours the injected arm; it is not evidence that the model reviewed worse.
4. **The arch adherence rubric was also vocabulary-literal.** It looked for "revers"; the discovered ADR said
   "Revisit when … a new ADR supersedes this one" and named two options, which is the same procedure in different
   words. Its frozen score is reported as measured, with this caveat rather than a post-hoc rewrite.
5. **Injection costs context and turns.** Input tokens rose ~67%, output ~71%, estimated cost ~32%, and requests
   per completed run rose from 4.55 to 5.6. Mean instruction overhead was +5,540 prompt tokens per run.
6. **No unnecessary-instruction event was observable**: no run reported or acted on an instruction outside its
   scenario, and every changed file stayed inside the owned path.

### Context accounting limits

Instruction size is `bytes / 4` of the prompt only. It excludes the Pi system prompt, tool definitions, the
17-skill discovery list, repository reads and conversation growth. Reported usage includes all of those, which is
why usage is much larger than the instruction estimate. No context-window enforcement was applied in this
experiment: the model's declared limit is 1,000,000 tokens and the largest observed input was far below it.
The figure cannot be used to claim exact context occupancy.

### A note on classification

The first summary treated the two 429-truncated runs as ordinary completions. The classification was corrected
after reading the transcripts, before writing this report: `summary-raw.json` keeps the original records and
`summary-classified.json` is the scored view. No run was repeated and no scenario changed.

## Recommendation

**Do not make direct injection the default swarm mechanism yet.** The measured direction is positive for
adherence, but the experiment is incomplete (9 of 12 runs), the arms are unbalanced by the request cap, and the
one acceptance difference comes from a hidden citation format that injection happened to teach. With n=4–5 per
arm, this is not enough to justify changing the default.

Keep injection opt-in (`--inject-skills`, default on in the controller) while the following would be needed for
a decision: balanced completed runs per arm, the citation convention either visible in the brief or removed from
acceptance, adherence scored on procedure rather than vocabulary, and a cap sized from observed requests per run
(at least 6 × requests/run per arm, i.e. 36 rather than 24 here).

If a default is forced by other constraints, the evidence supports injection for procedural skills where the
artifact convention is part of the deliverable (review, architecture) and no measurable benefit for a task whose
acceptance already forces the procedure (fix). That is a hypothesis, not a measured result.
